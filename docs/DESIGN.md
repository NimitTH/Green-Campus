## 1. ข้อห้ามและข้อจำกัด (ต้องทำตามทุกข้อ)

งาน redesign **เปลี่ยนหน้าตาอย่างเดียว ห้ามเปลี่ยนพฤติกรรม** ตอนนี้แอปมีเทสต์ e2e 134 ข้อ, vitest 556 ข้อ และ pgTAP 1021 ข้อ ผ่านทั้งหมด จบแต่ละขั้นต้องยังผ่านครบเหมือนเดิม

### 1.1 ห้ามแตะ logic

- ห้ามแก้ `supabase/migrations/**`, `supabase/tests/**`, `src/app/actions/**`, `src/lib/**` (ยกเว้นไฟล์ที่เป็นการแสดงผลล้วน และต้องระบุเหตุผลในแผน), `src/proxy.ts`, `src/app/api/**`, `scripts/**`
- ห้ามเปลี่ยนวิธีดึงข้อมูล, การตรวจสิทธิ์ (`requireStaff`, `requireAdmin`, `getCurrentUser`), `<Suspense>` และ `await connection()` ที่หน้าใช้อยู่ ถ้าย้ายโครงหน้า ต้องให้ส่วนที่อ่าน session ยังอยู่ใน `<Suspense>` (กติกาของ Cache Components ดู `AGENTS.md`)
- ห้ามเพิ่ม `'use cache'` ใหม่ หรือแก้ฟังก์ชันที่มี `'use cache'` อยู่แล้ว
- ห้ามเปลี่ยนชื่อหรือย้าย route (URL ทุกเส้นต้องเหมือนเดิม)
- PDF (`src/lib/pdf/**`) ไม่อยู่ในงานนี้ ใช้ฟอนต์ Sarabun ของตัวเองแยกจากเว็บ

### 1.2 ห้ามเปลี่ยนสิ่งที่เทสต์ใช้หาองค์ประกอบ

เทสต์หาองค์ประกอบด้วย `getByRole` 291 ครั้ง, `getByTestId` 140 ครั้ง, `getByLabel` 85 ครั้ง และ `getByText` 42 ครั้ง จึงห้ามเปลี่ยนสิ่งต่อไปนี้:

- **ข้อความภาษาไทย**บนปุ่ม ลิงก์ หัวข้อ ป้ายช่องกรอก ข้อความ error และสถานะว่าง เช่น "ยืนยันแลก", "ส่งผล", "อนุมัติ", "ดาวน์โหลดใบเสร็จ", "เตรียมของเสร็จแล้ว", "ไม่มีกิจกรรมที่จบในช่วงนี้", "บันทึกแล้ว"
- **ชื่อเมนู**:
  - เมนูล่างนักเรียน: หน้าหลัก / กิจกรรม / รางวัล / แจ้งเตือน / ฉัน
  - เมนูครู: หน้าหลัก, ตรวจผล, กิจกรรม, จุดชั่ง, ออเดอร์, ของรางวัล, บทความ, รายงาน, ผู้ใช้, อัตรา, โปรไฟล์, แจ้งเตือน, ออกจากระบบ
- **`data-testid`** ทั้ง 53 ค่า และ data attribute อื่น: `data-realtime`, `data-user-id`, `data-slug`, `data-bottom-nav`
- **landmark และ aria**: ป้าย `<nav aria-label="…">` (เช่น "เมนูหลัก" ของนักเรียน, "เมนูผู้ดูแล" ของครู, "เมนูสาธารณะ"), `aria-current`, `aria-expanded` / `aria-controls` ของลิ้นชักเมนูครู, `role="alert"` ของข้อความ error, `<label htmlFor>` ที่ผูกกับช่องกรอก
- **ชนิดองค์ประกอบ**: ปุ่มต้องเป็น `<button>` และลิงก์ต้องเป็น `<a>`/`<Link>` เหมือนเดิม ไอคอนทำแทนข้อความไม่ได้ ถ้าจะใส่ไอคอนต้องคงข้อความไว้ หรือใช้ `aria-label` ที่เป็นข้อความเดิม
- ถ้าจำเป็นต้องเปลี่ยนข้อความใด ต้องถามเจ้าของโปรเจกต์ก่อน แล้วแก้เทสต์ใน commit เดียวกัน ห้ามทำให้ assertion อ่อนลง

### 1.3 Next.js 16 ที่ต่างจากที่โมเดลรู้

- อ่าน `node_modules/next/dist/docs/` ก่อนแก้ layout หรือ component
- หน้าที่เคยเปิดแล้วถูกเก็บซ่อนไว้ใน `<Activity>` จึงต้องระวัง 2 อย่าง:
  - **ห้ามใช้ `id` ตายตัว**ในฟอร์ม ให้ใช้ `useId()` ไม่อย่างนั้นป้ายจะชี้ไปที่ช่องกรอกในหน้าที่ซ่อนอยู่
  - state ของฟอร์มต้องรีเซ็ตหลังบันทึกเหมือนที่ทำไว้แล้ว ห้ามรื้อออก
- ปุ่มสลับธีมต้องไม่ทำให้หน้ากระพริบตอนโหลด (ตั้ง class หรือ attribute ก่อนวาดหน้า) และต้องไม่ทำให้หน้าสาธารณะ (`/`, `/articles`) กลายเป็น dynamic ห้ามอ่าน cookie ในส่วนที่ cache ไว้
- ตอนนี้ธีมมืดใช้ `prefers-color-scheme` + คลาส `dark:` ประมาณ 290 จุด ถ้าเปลี่ยนเป็นสลับเองได้ ให้ใช้ `@custom-variant dark` ของ Tailwind 4 และต้องยังรองรับ "ตามระบบ"

### 1.4 มือถือและการใช้งาน

- **ต้องไม่มีแถบเลื่อนแนวนอนที่ความกว้าง 360 px** (มีเทสต์ตรวจ `scrollWidth`)
- เมนูล่างนักเรียน:
  - มี 5 ปุ่มคงที่ แสดงเฉพาะบนมือถือ (`md:hidden`)
  - จุดกดสูงอย่างน้อย 44 px (ตอนนี้ 56 px)
  - เว้นขอบล่าง safe-area และเว้นที่ด้านล่างเนื้อหาไม่ให้ถูกบัง (มีเทสต์ตรวจ)
  - ไอคอนแจ้งเตือนแสดงจำนวนที่ยังไม่อ่าน
- เมนูครู:
  - จอคอมเป็นแถบข้าง ปรากฏตั้งแต่ขนาด `xl`
  - มือถือเป็นลิ้นชัก: ปิดด้วย Esc ได้ เปิดแล้วโฟกัสย้ายเข้าเมนู ปิดแล้วโฟกัสกลับที่ปุ่ม ปิดเองเมื่อเปลี่ยนหน้า
  - เมนูผู้ใช้กับอัตราแสดงเฉพาะ admin ตัดสินที่เซิร์ฟเวอร์
- **หน้าจุดชั่ง** (`/staff/weigh-station`) ใช้ยืนที่จุดชั่ง ต้องคงไว้: ปุ่มใหญ่, รหัส 6 หลักตัวใหญ่, นับถอยหลังชัด และแถบข้างต้องไม่บีบพื้นที่บนแท็บเล็ต
- ทุกหน้าที่ดึงข้อมูลมีสถานะกำลังโหลดและสถานะว่างอยู่แล้ว ห้ามลบ
- ความต่างของสี (contrast) ต้องผ่าน WCAG AA ทั้งธีมสว่างและมืด (ข้อความปกติ 4.5:1, ข้อความใหญ่และขอบปุ่ม 3:1) สีเขียวสดบนพื้นขาวมักไม่ผ่าน ต้องเช็ก
- ต้องมี focus ring ที่มองเห็นได้ทุกองค์ประกอบที่กดได้
- เคารพ `prefers-reduced-motion`

### 1.5 ฟอนต์และภาษา

- ทั้งเว็บเป็นภาษาไทย (`<html lang="th">`) ฟอนต์ต้องรองรับสระและวรรณยุกต์ซ้อน (ที่ น้ำ ผู้ ญี่ปุ่น ปั้น) และ line-height ต้องพอไม่ให้วรรณยุกต์ชนบรรทัดบน
- ตอนนี้ใช้ Sarabun ผ่าน `next/font/google` (`--font-sarabun`) จะเพิ่มฟอนต์หัวข้อได้ แต่ต้องโหลดผ่าน `next/font` และมีอักษรไทย ห้ามโหลดจาก CDN ตรง
- ตัวเลขใช้ `th-TH` และวันที่ใช้เขตเวลา Asia/Bangkok ตามที่มีอยู่ ห้ามเปลี่ยนรูปแบบ

### 1.6 กราฟ รูป และไลบรารี

- กราฟใช้ Recharts 3.10.1 (`src/components/charts/WasteByCategory.tsx` ตอนนี้ใช้สีตายตัว `#16a34a`) ให้เปลี่ยนเป็น token ของธีม ต้องอ่านได้ทั้งธีมสว่างและมืด

- **ห้ามเพิ่ม dependency** ถ้าไม่ได้ตกลงกับเจ้าของโปรเจกต์ก่อน (เช่น ไลบรารีไอคอนหรือ UI kit) ห้ามใช้ `npm --force` / `--legacy-peer-deps`

## 2. ทิศทางการออกแบบ

> ตกลงกับเจ้าของโปรเจกต์ 24 ต.ค. 2026 (brainstorming) · แนวทางที่เลือก: **token เชิงความหมาย + ชิ้น UI กลาง** (ไม่ใช่ remap สีอย่างเดียว และไม่ใช่ class กลางแบบ Coral)

**อารมณ์: "สมุดบันทึกภาคสนามบนกระดาษดี"** เรียบ อุ่น เชื่อถือได้ ตัวเลขชัดเหมือนบันทึกจริง

**หยิบจาก Hallmark Coral** (อ้างอิงไฟล์ `tokens.css` / `style.css` / `base.css` ของธีม ไม่มีสกิล hallmark ติดตั้งในเครื่อง):

- พื้นกระดาษอุ่น + ตัวอักษรสีหมึกเข้ม + **สีเน้นสีเดียว** (เปลี่ยนจากปะการังเป็นเขียวใบไม้)
- หัวข้อใหญ่ ตัวหนา tracking แน่นเล็กน้อย, `text-wrap: balance`
- ปุ่มหลักเป็น "การ์ด" มีเงาตกไปทางขวาล่าง (แสงมาจากซ้าย) ยกขึ้น 1px ตอน hover กดลง 1px ตอน active
- ตัวเลขสถิติเป็น monospace (`tabular-nums`)
- ระยะห่างเยอะ, เส้นแบ่งบาง (hairline), easing `cubic-bezier(0.16, 1, 0.3, 1)`

**ไม่เอา:** ลายผิวกระดาษ (SVG texture), ฉาก still-life ทำด้วย CSS, เงาพิมพ์นูนหลายชั้น, `line-height` 1.05 ของหัวข้อ (วรรณยุกต์ไทยชน), General Sans (ไม่มีอักษรไทย)

**ธีมมืด:** ไม่ใช่การกลับสี แต่เป็น "ป่าตอนกลางคืน" พื้นเขียวดำ ตัวอักษรขาวอุ่น สีเน้นเป็นเขียวมิ้นท์สว่าง

### 3.2 ตัวกันช่วงเปลี่ยน: remap gray / green

โค้ดเดิมใช้ `gray` 568 จุด, `green` 218 จุด, `red` 214 จุด, `amber` 60 จุด ชั้นที่ 1 จะ **override `--color-gray-50…950` เป็นโทนกลางอุ่นอมเขียว (hue 95–155, chroma ≤ 0.02)** และ **`--color-green-50…950` เป็นสเกลเขียวใบไม้ (hue 150)** ใน `@theme` เพื่อให้หน้าที่ยังไม่ย้ายไม่ขัดกับหน้าที่ย้ายแล้ว ลำดับความสว่างของแต่ละขั้นต้องใกล้ของเดิม (±3% L) เพื่อไม่ให้ contrast ของคลาสเดิมตก เมื่อย้ายครบทุกชั้นแล้ว ตรวจว่าเหลือคลาส gray/green ดิบเท่าไร (เป้า: เหลือเฉพาะจุดที่มีเหตุผล)

### 3.3 ฟอนต์และขนาด

ทั้งหมดโหลดผ่าน `next/font/google` ใน `src/app/layout.tsx`:

| บทบาท | ฟอนต์ | น้ำหนัก | ตัวแปร |
|---|---|---|---|
| หัวข้อ | IBM Plex Sans Thai (subsets `thai`, `latin`) | 600, 700 | `--font-display` → utility `font-display` |
| เนื้อหา | Sarabun (เดิม) | 400–700 | `--font-sarabun` → `font-sans` |
| ตัวเลขสถิติ / รหัส 6 หลัก | Geist Mono (`latin`) | 400, 600 | `--font-mono` → `font-mono` |

- Geist Mono ใช้กับตัวเลขและหน่วยภาษาอังกฤษเท่านั้น (ไม่มีอักษรไทย) ตัวเลขยังจัดรูปแบบด้วย `th-TH` เหมือนเดิม
- ขนาด: `display` = `clamp(2.25rem, 4vw + 1rem, 3.75rem)` (หน้าแรก), `h1` = `clamp(1.75rem, 2vw + 1rem, 2.25rem)`, `h2` = `1.5rem`, `h3` = `1.25rem`, เนื้อหา `1rem`, เล็ก `0.875rem`
- **line-height หัวข้อ ≥ 1.25**, เนื้อหา 1.6, tracking หัวข้อ `-0.01em` (ไทยไม่รับ tracking ติดลบมาก)

### 3.4 ระยะ มุม เงา การเคลื่อนไหว

- ระยะใช้สเกล Tailwind เดิม, ช่องว่างข้างจอ 16px (มือถือ) / 24px (md) / 40px (xl), ระยะระหว่าง section หน้าแรก 72px (มือถือ) / 120px (จอคอม)
- มุม: การ์ด `--radius-card: 8px`, ช่องกรอกและปุ่ม `--radius-input: 6px`, badge และ pill `999px`
- เงา (ธีมมืดลดความเข้มเพราะพื้นมืดอยู่แล้ว):
  - `--shadow-card`: `0 1px 2px` เงาจาง 5%
  - `--shadow-cast`: `6px 5px 10px -6px` เงา 30% (ปุ่มหลัก, การ์ดสถิติ)
  - `--shadow-cast-lift`: `12px 10px 18px -8px` เงา 30% (ตอน hover)
- เวลา: `--dur-micro 120ms`, `--dur-short 220ms`, easing `--ease-out cubic-bezier(0.16, 1, 0.3, 1)`
- `prefers-reduced-motion: reduce` → ปิด transform และ transition ทั้งหมด (ปุ่มไม่ยก/ไม่กด)

### 3.5 การสลับธีม

ทำตาม `node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`:

1. `<html lang="th" suppressHydrationWarning>` ใน `src/app/layout.tsx` และสคริปต์ inline ใน `<head>` อ่าน `localStorage.theme` ถ้าเป็น `"light"` หรือ `"dark"` ตั้ง `data-theme` บน `<html>` ก่อนวาดหน้า มี `try/catch` (localStorage อาจใช้ไม่ได้)
2. **"ตามระบบ" = ไม่มี `data-theme`** ให้ `prefers-color-scheme` ทำงาน (ไม่เก็บค่า หรือลบ key ทิ้ง)
3. **ไม่ใช้ cookie และไม่อ่าน `cookies()`** หน้าสาธารณะจึงยัง static
4. Tailwind:
   ```css
   @custom-variant dark {
     &:where([data-theme=dark], [data-theme=dark] *) { @slot; }
     @media (prefers-color-scheme: dark) {
       &:where(:root:not([data-theme=light]), :root:not([data-theme=light]) *) { @slot; }
     }
   }
   ```
   token สีใช้กติกาเดียวกัน: `:root` = สว่าง, `[data-theme=dark]` และ `@media (prefers-color-scheme: dark) { :root:not([data-theme=light]) }` = มืด พร้อม `color-scheme` ให้ตรง (scrollbar และช่องกรอกของเบราว์เซอร์)
5. `ThemeToggle` (client component) re-apply attribute ใน `useLayoutEffect` ตามคู่มือ (Strict Mode ตอน dev ล้าง attribute บน `<html>`) และเปลี่ยนค่าแล้วเขียน `localStorage` + ตั้ง/ลบ attribute ทันที
6. ค่า `"theme"` ใน localStorage ที่ไม่ใช่ `light`/`dark` ถือเป็น "ตามระบบ"

## 4. Component

ชิ้นใหม่อยู่ใน `src/components/ui/` ทุกชิ้นเป็น **wrapper บาง**:

- render element เดิม (`<button>`, `<a>`/`<Link>`, `<label>`, `<input>`, `<span>`)
- ส่งต่อ `...props` ทั้งหมด (รวม `data-testid`, `aria-*`, `id`, `type`, `disabled`, `form`) และต่อ `className` ท้ายสุด
- **ไม่สร้างข้อความเอง** ข้อความทั้งหมดมาจาก `children` ที่หน้าส่งมา (ยกเว้น `ThemeToggle` ที่เป็นข้อความใหม่)
- ไม่มี `id` ตายตัว
